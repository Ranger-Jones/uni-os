# UniOS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build UniOS, a Notion-inspired macOS desktop app for managing university courses, notes, assignments, schedule, files, grades and flashcards, with an in-app LLM chat (Claude/OpenAI) and an MCP server.

**Architecture:** Electron app built with electron-vite. A pure-TypeScript `src/core` (SQLite schema, repositories, domain logic, LLM tool definitions) is shared by the Electron main process and a stdio MCP server. The React renderer talks to main through one typed IPC router.

**Tech Stack:** Electron 45, electron-vite 6, React 19, TypeScript, Tailwind v4, TanStack Router + Query, Zustand, better-sqlite3 + Drizzle ORM, BlockNote 0.56 (mantine variant) + @blocknote/server-util, ts-fsrs, unpdf, @anthropic-ai/sdk, openai, @modelcontextprotocol/sdk, zod, vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-24-unios-design.md`

## Global Constraints

- UI language: English. Platform: macOS (Apple Silicon). Package manager: pnpm.
- `src/core` must not import `electron` or anything from `src/main`/`src/renderer`.
- All DB access goes through `src/core/repo/*`. IDs: `crypto.randomUUID()`. Timestamps: ISO 8601 strings. Dates without time: `YYYY-MM-DD`. Times: `HH:MM`.
- SQLite: WAL mode, `foreign_keys = ON`, `busy_timeout = 5000`.
- Grades: German scale 1.0–5.0, passed if ≤ 4.0, display truncated to one decimal, GPA weighted by ECTS over `grading_mode = 'graded'` courses only.
- API keys only via Electron `safeStorage`; never sent to the renderer.
- Mutating LLM tools require user approval in the in-app chat.
- Tests run under Electron's Node (`ELECTRON_RUN_AS_NODE=1`) so better-sqlite3 has one native build.
- Each phase ends with `pnpm typecheck && pnpm test` green and a commit.

## Review Focus

1. **Concurrent writes from MCP while the app is open** — app must pick up changes (data_version polling) and never show stale data or crash on `SQLITE_BUSY`. Test: core test opening two connections to one file, write on B, `dataVersion` on A changes.
2. **Course with no graded components / weights not summing to 100 / pass-fail courses** — grade view must show "–" or "provisional", never NaN, and GPA must ignore them. Tests in Task 4.1.
3. **Deleting a course with pages, files, assignments, cards** — cascades cleanly, files removed from disk, search index entries removed. Test in Task 1.2 (cascade) and 5.1 (file removal).
4. **Large/scanned PDFs** — extraction of a PDF without text layer yields `text = null` without failing the import; very long texts are paged by `read_file_text`. Test in Task 5.1 and 6.1.
5. **LLM tool inputs that reference non-existing IDs or invalid values** (e.g. grade 6.0, unknown course) — handler returns a structured error the model can read, never throws through to the UI. Tests in Task 6.1.
